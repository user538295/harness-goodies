/double-check

← Vissza az áttekintéshez

Összefoglaló

Minden megbízható reviewer, egy célpont, egy összefésült találatlista. A projekt .double-check.json fájljának minden elemét — skilleket és parancsokat, ágenseket, MCP-szervereket, CLI-eszközöket, Markdown szabályfájlokat — ugyanazon a célponton futtatja le, majd az eredményeket találatonként egy sorba vonja össze, súlyosság szerint rendezve.

Csak olvas. Soha nem szerkeszti, stage-eli vagy commitolja az átvizsgált fájlokat; az egyetlen projektfájl, amit ír, a .double-check.json.

Mikor használd

Lefuttatod a /da-review-t, aztán a /clean-code-review-t, aztán a lintert, aztán eszedbe jut, hogy az AGENTS.md-ben is vannak szabályok — és mindegyik a saját formátumában válaszol. A /double-check mindet párhuzamosan futtatja, előtte ellenőrzi, hogy tényleg telepítve és használatra kész-e, és öt riport helyett egyetlen listát ad.

A skill a parancson túl nem deklarál trigger kifejezéseket. Hívd meg a /double-check paranccsal, kérd, hogy az összes beállított reviewerrel ellenőrizze a változásokat vagy fájlokat, vagy kérdezd meg, mely beállított reviewerek érhetők el.

Meghívás

/double-check [TARGET] [elemenkénti paraméterek]
/double-check init
/double-check status

Célok (alapértelmezett: összes helyi változás):

  • nincs vagy local — staged, unstaged és untracked változások. Git nélkül nincs mit diffelni, ezért a skill megkérdezi, mit ellenőrizzen.
  • Egy ref — abc123, HEAD — a commit által érintett fájlok.
  • Egy tartomány — A..B vagy A...B. A commit és a tartomány cél gitet igényel; git nélkül a futás ezzel áll le: Nothing to check: not a git repository.
  • Fájlok, mappák vagy glob-minták — *.h tests/. Git nélkül is működik.
  • Leírt fájlhalmaz — all files except tests/. Félreérthető szövegnél a skill megkérdezi, mely fájlokra gondolsz, mielőtt folytatná.

Elemenkénti paraméterek a célponttal egy mondatba kerülnek: /double-check check src/ and run shellcheck with -S warning. A konfigban az egyes bejegyzések args mezőjével együtt érvényesek; egy futásra ütközésnél a meghíváskor megadott érték győz, a fájl változatlan marad.

.double-check.json a projekt gyökerében áll (a git legfelső könyvtárában, git nélkül az aktuális könyvtárban). JSON tömb; minden bejegyzésnek pontosan egy típuskulcsa van, plusz opcionális args string:

  • { "skill": "/brooks-review" } — skill, parancs vagy plugin
  • { "agent": "security-reviewer" } — ágens-típus
  • { "mcp": "playwright" } — csatlakoztatott MCP-szerver
  • { "tool": "eslint", "args": "--max-warnings 0" } — CLI-eszköz
  • { "md": "conventions.md" } — szabályokat és irányelveket tartalmazó Markdown fájl

Ha a fájl hiányzik, a skill létrehozza az alapértelmezett konfiggal — /da-review, /clean-code-review, /brooks-review, /open-code-review, markdownlint, shellcheck, és az AGENTS.md szigorú szabályfájlként —, és egy sorban szól. A hibás bejegyzést (nem objektum, nulla vagy több típuskulcs, nem string args) és az ismeretlen kulcsot soronként felsorolja javasolt javítással, és a javított konfiggal folytatja.

init létrehozza az alapértelmezett konfigot és kiírja az útvonalát — ha a fájl már létezik, csak az útvonalat írja ki, a fájlhoz nem nyúl. A status kiírja minden beállított elemet az args mezőjével és az elérhetőségével — ✅ 🛠 eslint (args: --max-warnings 0) — és semmit nem vizsgál át.

Elérhetőségi kapu. Mielőtt bármelyik reviewer elindul, a skill kiír egy Check availability: blokkot: elemenként ✅ vagy ❌, egy skill függőségei külön sorban fölötte. Okok: not found · not installed · not connected · not ready: … · installed, but there is no … in the target · not applicable: … · missing dependency …. Ami titok és a te döntésed nélkül javítható — egy dokumentált CLI telepítése —, azt magától megcsinálja. Ami interaktív (hitelesítő adatok, bejelentkezés), ott a futás megáll, amíg nem válaszolsz: retry, continue (review nélkülük), vagy stop. A skill titkot sosem kér chatben.

Hogyan futnak az elemek. Minden elem külön subagentben fut, párhuzamosan; a nehéz vagy lassú elemek saját subagentet kapnak, a gyors, determinisztikus eszközök közösen egyet. Az eszközök natív súlyosságát a rubrikára képezi le (shellcheck error → Major, warning → Moderate, info/style → Minor). Ha a harnessben nincs subagent eszköz, az elemek inline futnak, és az összegzés kiírja: Review ran inline, not independent.

Találatsor — találatonként egy sor, legfeljebb 255 karakter:

emoji [item] · Severity · Short name/category | path/to/file.ext:N | Explanation and a short fix.

Ugyanaz a gyökérok ugyanazon a helyen több elemtől egy sorba olvad össze, az elemek vesszővel elválasztva. Rendezés: súlyosság, majd útvonal, majd sorszám. A lefutás közben elhasalt vagy a kapunál kihagyott elemek a záró Not run: blokkba kerülnek.

Súlyossági szintek: Kritikus (helyességet, biztonságot vagy védettséget akadályoz) · Súlyos (jelentős tervezési hiba, hiányzó követelmény vagy valószínű bug) · Közepes (nem optimális, de működőképes) · Apró (stílus, elnevezés vagy szőrszálhasogatás)

1. példa — Helyi változások, alapértelmezett konfig (szemléltető példa)

Bemenet:

/double-check

Kimenet / eredmény:

Target: local — 4 files

Check availability:
   ✅ 🧠 /devils-advocate
   ✅ 💡 /da-review
   ✅ 💡 /clean-code-review
   ✅ 💡 /brooks-review
   ✅ 💡 /open-code-review
   ✅ 🛠 markdownlint
   ❌ 🛠 shellcheck: installed, but there is no shell script in the target
   ✅ #️⃣ AGENTS.md

💡 [da-review] · Major · Unchecked payment result | src/services/PaymentProcessor.ts:34 | charge() result is ignored; an order can be marked paid without payment. Check the result before updating status.
💡💡 [clean-code-review, brooks-review] · Major · Single Responsibility | src/services/UserService.ts:12 | Split UserService: move auth, email, and billing into separate classes.
#️⃣ [AGENTS.md] · Moderate · Avoid magic numbers | src/services/PaymentProcessor.ts:58 | Replace the literal 3 with a named RETRY_LIMIT constant.
🛠 [markdownlint] · Minor · MD022 | README.md:14 | Surround the heading with blank lines.

2. példa — Commit-tartomány egy elakadt reviewerrel (szemléltető példa)

Bemenet:

/double-check HEAD~2..HEAD

Kimenet / eredmény:

Target: range HEAD~2..HEAD — 6 files

Check availability:
   ✅ 🧠 /devils-advocate
   ✅ 💡 /da-review
   ✅ 💡 /clean-code-review
   ❌ 💡 /open-code-review: not ready: no LLM provider configured (ocr llm test failed)
   ✅ 🛠 markdownlint

Blocked — run the fixes, then answer `retry`, `continue` (review without them), or `stop`:
   ❌ 💡 /open-code-review: not ready: no LLM provider configured (ocr llm test failed) → run: ocr config provider

Bemenet:

continue

Kimenet / eredmény:

💡 [clean-code-review] · Critical · [safety-01] Resource Leak | src/db/session.py:23 | Wrap the connection in a `with` block so it is closed on every path.
💡 [da-review] · Moderate · Missing migration test | tests/test_migrate.py:1 | Add a test that runs the new migration on a non-empty table.

Not run:
   ❌ 💡 /open-code-review: not ready: no LLM provider configured (ocr llm test failed)

Kapcsolódó eszközök

  • /da-review — Egymenetes, ellenpárti review. Az alapértelmezett /double-check elemek egyike; egyedül akkor futtasd, ha egy vélemény elég.
  • /clean-code-review — 132 ellenőrzés 7 csoportban. Szintén alapértelmezett elem; a /double-check ugyanazt a célpontot adja neki, és a találatait beolvasztja a közös listába.
  • /iterative-review — Hurokban review-zik és javít. A /double-check csak listáz, és semmit nem módosít; az /iterative-review-hoz akkor nyúlj, ha a problémák meg is oldódjanak.
