What it is

/session-log writes the prompt and response text exposed by the current harness to a local Markdown transcript. It supports exactly five host identities: Claude Code, Codex, Cursor, OpenCode, and OMP.

The same four commands control every harness, but their reports are deliberately not identical. Each adapter uses only its native lifecycle and usage records: Cursor exposes per-turn token counts in hook payloads but not in transcripts, while Codex exposes token totals through native rollout records.

What you get

  • A readable session transcript. Native lifecycle events append available prompts, final responses, and sub-agent notices in chronological order to a private local Markdown file.
  • Truthful native usage. Claude Code and OMP can report per-turn usage; OpenCode reports native main-session and sub-agent aggregates; Codex reports a native rollout TOTAL. Cursor reports a TOTAL of the token counts its stop hook recorded, for the parent agent only.
  • Native timing and cost where available. Claude Code calculates an offline price estimate; OpenCode and OMP preserve their native cost fields. Codex and Cursor report token fields without price or working-time figures.
  • Native sub-agent accounting where available. Claude Code, OpenCode, and OMP include the sub-agent records their stores expose. Report fields and grouping remain harness-specific.
  • An explicit identity boundary. The universal skill asks the current host/model to select claude, codex, cursor, opencode, or omp; it never infers identity from paths, processes, or environment variables.
  • Local and private. Managed log files use 600 permissions and nothing is uploaded by this package.

The four commands

Run /session-log with one of these. With no argument it defaults to status.

CommandWhat it doesTypical output
on Installs the current harness adapter and turns logging on. <label>: on or on — restart required; Codex uses on — trust review/restart required
off Turns logging off for the current harness. <label>: off
status default Repairs an enabled adapter if needed, then reports whether it is active. on / off / on — adapter missing / on — restart required; Codex uses on — trust review/restart required
usage Runs the current harness's native usage report. <label>: usage and a native report

The exact labels are Claude Code, Codex, Cursor, OpenCode, and OMP. usage defaults to the latest native session; pass a session ID, or a transcript path where that adapter accepts one. OpenCode accepts only an ID or --latest. Claude Code alone accepts --check to compare with ccusage when installed.

Good to know

  • Install all five without enabling them. From the repository, run bash install-universal-session-log.sh. It seeds or updates a complete stable package in every default skill root and installs OpenCode's command entrypoint.
  • Bootstrap one harness while running a command. For example, bash skills/session-log/install.sh --harness cursor --arguments "status" first seeds or updates Cursor's package, then dispatches status. Use --install --harness <identity> to seed one package without running a command.
  • Activation is per harness. on, off, and status touch only the explicitly selected identity. Restart after on — restart required. For Codex, review the commands added to ~/.codex/hooks.json, trust them, then restart.
  • Enabled adapters recover automatically. Every installer dispatch refreshes the selected stable package. If logging is enabled, status and usage also reinstall a missing or outdated native adapter before continuing.
  • Usage is not a common schema. Claude Code reports per-turn and sub-agent totals with offline price estimates; OpenCode and OMP preserve native token and cost data; Codex totals native rollout token records without price; Cursor sums the parent agent's token counts that its stop hook recorded while logging was on with the current adapter (subagentStop carries no tokens) and fails explicitly when a session has no records.
  • Dependencies are command-specific. Package bootstrap needs bash, Python 3, and shasum or sha256sum; runtime-state checks and Claude Code need jq. OpenCode usage additionally needs sqlite3; OMP usage needs Bun. ccusage is optional for Claude Code's --check.
  • Default roots only. The roots are ~/.claude, ~/.codex, ~/.cursor, ~/.config/opencode (with native data in ~/.local/share/opencode), and ~/.omp/agent. Relocated roots fail explicitly.

What a logged turn looks like

Scenario: one full turn — you submit a prompt, a background sub-agent finishes, the assistant answers, and you had switched model and effort since the previous turn. This is what lands in the session file (Claude Code, ~/.claude/prompt-logs/<project>/session_….md):

## 14:02:11

Implement the next uncompleted task in plans/FEAT-001.md

---

14:03:05 sub-agent finished: general-purpose (agent-9f3c2a1b), jsonl: /Users/…/<sid>/subagents/agent-9f3c2a1b.jsonl

### 14:05:53 response

<the assistant's final message, verbatim>

working time: 00:03:42
est. used token: input: 2000, output: 1000, cache_create: 150000, cache_read: 0, total_tokens: 153000, price: $2.32, model: claude-opus-5, effort: max
switched: model claude-sonnet-5 → claude-opus-5, effort high → max

---

Reading top to bottom: the prompt, then the sub-agent that ran, then the reply, then the measurements. total_tokens is input + output + cache-write + cache-read. The switched: line here explains the large cache_create: changing models forced a full cache write on this turn.

What a Claude Code usage report looks like

Command: /session-log usage in Claude Code (totals the newest session of the current project). Other harnesses keep their native report shapes described above.

Claude Code: usage

1. 14:02:11  Implement the next uncompleted task…   est. used token: … price: $2.32
2. 14:12:40  Fix the failing test in auth_test…      est. used token: … price: $0.41
   sub-agent general-purpose (agent-9f3c2a1b)         est. used token: … price: $0.77

TOTAL (2 requests, 1 sub-agent)  input: … output: … total_tokens: …  price: $3.50

One numbered line per turn, one line per sub-agent transcript found under the session, then a merged TOTAL. Every transcript is counted once, no matter how deeply sub-agents nest.
