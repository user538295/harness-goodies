# Skill & command paths — harness-agnostic (Claude Code, Cursor, OpenCode, omp, Codex)

Everything under `skills/` and `commands/` must run unchanged in every harness. When a SKILL.md or command needs its own bundled files, follow these rules — they were learned the hard way (the same Claude-Code-only locator snippet had drifted into 7 files before `clean-code-review` fixed it).

- **`$BASE` (the skill's own directory) comes from the harness first.** Claude Code and OpenCode print `Base directory for this skill: <path>` when a skill loads; omp prints `[Skill directory: <path>]`; in Cursor it is the directory of the SKILL.md that was read. Tell the model to use that path verbatim.
- **Fallback only when nothing was announced.** Copy the locator from `skills/clean-code-review/SKILL.md` Step 0 verbatim, swapping only the skill name, its `<SKILL>_HOME` override variable, and the probe file it tests. It is the single golden copy — do not fork variants. Order: explicit `<SKILL>_HOME` override → project-level roots → user-level roots of every supported harness (Claude Code, Cursor, OpenCode, omp, Codex) → plugin caches: newest Claude Code and omp marketplace copies (`sort -V` on their version directories), then the most recently installed Cursor marketplace and OpenCode package copies (`ls -dt`, because their cache directories are commit SHAs and install stamps, not versions). It probes with `[ -f ]`, so symlinks are followed and stale (dangling) ones are skipped. The **resolution loop** (`for d in … done`) is the part that must stay verbatim; the **terminal action** after it legitimately differs by how the skill uses `$BASE` — echo the path (clean-code-review, implement, llm-wiki, md-reviewer, documentation-standard), run a bundled script directly from it where a skill does that (`skills/session-log/SKILL.md` execs its `install.sh`, erroring when the package is absent), or, where a not-found is a normal no-op rather than an error, silently skip without the `echo ERROR … >&2` branch. Keeping the loop identical is what "do not fork variants" means.
- **Never locate a skill through Claude Code artifacts:** no `CLAUDE_PLUGIN_ROOT`, no `${CLAUDE_SKILL_DIR}`, no `~/.claude/plugins/installed_plugins.json`, no `jq`, no bare `~/.claude/skills` fallback. No `CLAUDE_*` path variable is exported to the Bash tool (verified on Claude Code 2.1.267), and `${CLAUDE_SKILL_DIR}` is a Claude-Code-only text substitution that is broken for plugin-installed skills (anthropics/claude-code#81588).
- **Write bundled paths relative to the skill root** (`scripts/x.sh`, `references/y.md`), as the Agent Skills spec requires — and always execute or read them as `$BASE/<path>`. Never run them bare and never `cd "$BASE"`: no harness sets the shell's cwd to the skill directory, and scripts must keep running from the user's repository.
- **Scripts self-locate:** `SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` (see `skills/clean-code-review/scripts/collect.sh`), so a script only has to be *found*, never told where it lives.
- **Portable frontmatter only:** `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`. No Claude-Code-only frontmatter fields or body features (`` !`cmd` `` injection, `${CLAUDE_*}` substitutions, `@file` imports) in anything that must run outside Claude Code.
- **Test it.** Any change to a locator block extends a fixture test like `skills/clean-code-review/tests/test_locator.sh`, which extracts the snippet from the SKILL.md verbatim and runs it against every harness's on-disk layout (roots, symlinks, dangling links, multi-version plugin cache, override, not-found).

Skill roots per harness, for reference — Claude Code: `~/.claude/skills`, `.claude/skills`, plugin cache `~/.claude/plugins/cache/*/claude-goodies/<version>/skills` (does **not** read `.agents/skills`). Cursor: `.agents/`, `.cursor/`, `.claude/`, `.codex/` `skills` (project and `~/`), marketplace cache `~/.cursor/plugins/cache/*/cursor-goodies/<commit>/skills`. OpenCode: `.opencode/`, `.claude/`, `.agents/` `skills` (project) and `~/.config/opencode/skills`, `~/.claude/skills`, `~/.agents/skills`, package cache `~/.cache/opencode/npm/*/<install stamp>/node_modules/opencode-goodies/skills`. omp: `~/.omp/agent/skills`, `.agents/skills`, `~/.agents/skills` (Claude user-level roots are opt-in), marketplace cache `~/.omp/plugins/cache/plugins/*___omp-goodies___<version>/skills`. Codex: `.codex/skills` (project and `~/`) — the roots the fallback locator probes for it.
